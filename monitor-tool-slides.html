Monitor vs /loop

Manual Polling

You keep asking “is it ready?” — Claude is blocked, every check costs tokens.

BLOCKING · N× TOKENS

/loop

Fires a prompt every N minutes. Non-blocking, but each iteration is a full API call.

TIME-DRIVEN · N× TOKENS

Monitor

Script watches silently. Only fires when stdout prints. Zero cost while waiting.

EVENT-DRIVEN · 1× TOKENS
When to use /loop instead: When you need Claude's full reasoning each check — like reviewing a PR diff every hour, or summarising new Slack messages. /loop re-runs a full prompt; Monitor just passes through raw stdout events.

Stream vs Poll
Two patterns for writing monitor scripts. Pick based on whether a data stream already exists.
patterns
STREAM FILTER A data stream already exists. You just filter for what matters. // Log tailing tail -f app.log \   | grep --line-buffered "ERROR" // File system watching fswatch -r ./uploads // Docker events docker events \   --filter event=die Continuous. Uses persistent: true
POLL & DIFF No stream exists. You create one by checking periodically. // Price check while true; do   curl -s api/price \     | check_threshold   sleep 30 done // Only prints when threshold hit Periodic. 30s+ for remote APIs
