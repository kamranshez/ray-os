**1. Delete Your CLAUDE.md (The Peer-Reviewed Case)**
A rigorous SWE-bench study found LLM-generated context files (AGENTS.md / CLAUDE.md) actually *reduce* task success (-3%) while inflating inference cost 20%+, and developer-written ones barely help (+4%). This inverts the single most-repeated piece of AI coding advice. The video can walk the paper's methodology, replicate Theo's with/without timing experiment live, and land on the principle of minimal, corrective context files.
- Why it works: counter-intuitive, benchmark-backed, attacks received wisdom, fits the "things everyone does that secretly make it worse" format.
- Original source: *Evaluating AGENTS.md (Gloaguen et al., 2026, ICML)* - https://arxiv.org/abs/2602.11988

**2. Stop Calling MCP Tools Directly (Write Code Instead) - 98.7% Token Reduction**

This is Anthropic effectively admitting their own protocol's default usage pattern is catastrophically inefficient.
- Why it works: official primary sources, hard numbers, a live before/after token demo, immediately implementable.

**3. Build for the Model 6 Months From Now (The Claude Code Lesson)**

**4. Stop Prompting Agents - Write Loops That Prompt Themselves**
The Boris Cherny / Peter Steinberger paradigm shift: you no longer prompt an agent, you design the loop that prompts the agent, with verifiable stopping conditions and maker/checker subagent splits. Theo validated it personally (shipped more code via self-prompting loops than manual prompting) and now says most agent runs should use machine-generated prompts.
- Why it works: clearest 2026 paradigm shift, directly maps to Claude Code's /loop and /goal primitives, sticky "loop author not prompter" reframe.
- Original sources: Addy Osmani "Loop Engineering" (quoting Boris Cherny) - https://addyo.substack.com/p/loop-engineering; Peter Steinberger "Stop prompting. Design loops." - https://x.com/steipete/status/2063697162748260627

**5. Run Claude in a Bash Loop OUTSIDE the Agent (The Ralph Architecture)**
The control-inversion lesson: the widely-used Ralph plugin runs the loop *inside* Claude Code, so context still accumulates and compacts and the agent never truly starts fresh. The correct topology puts the while-loop *outside* as a shell script that kills and reinstantiates the agent each iteration, making a file on disk (not the context) the source of truth. Pairs with the related insight that compaction silently drops critical instructions.
- Why it works: clean "who owns whom" architectural principle, a simple two-topology diagram, generalizes to any multi-step agentic system.
- Original source: Jeff Huntley "Ralph" - https://ghuntley.com/ralph/ (and Ryan Carson's guide - https://github.com/snarktank/ralph)
- Theo video: "We need to talk about Ralph" - https://www.youtube.com/watch?v=Yr9O6KFwbW4

**8. More Context Makes Your Agent Dumber (The Context Rot Cliff)**

**11. The Re-Roll Formula: Why a Faster, Dumber Model Wins in Loops**
Theo works the math live: an 80%-accurate model at 0.5 min/run reaches 99.9% confidence in ~2 min, while a 90%-accurate model at 4 min/run needs 12 min for the same confidence. For iterative agentic work, total time-to-correct often favors the faster model because you re-roll faster than the slow model completes once. This reframes model selection from "pick the smartest" to "optimize iteration velocity," and connects to running N models in parallel and picking the first passing output.
- Why it works: genuinely non-obvious, quantified, lends itself to a simple interactive calculator, directly actionable for Haiku-vs-Sonnet decisions.
- Original source: none cited (Theo's own derivation) - present as an original framework, optionally pair with Cursor's multi-model racing (https://cursor.com/blog/2-0).

**12. Why Your Agent Sends the Same Context 100 Times (and the WebSocket Fix)**
The foundational mental-model failure: every tool call resends the *entire* accumulated history from token zero (the model is stateless, "dead" between calls), and prompt caching reduces compute but NOT bandwidth because the cache key is a hash of that full history. OpenAI's WebSocket mode fixes this by guaranteeing a persistent connection to the same box, yielding 20-40% speedups on 20+ tool-call runs and 90%+ bandwidth reduction.
- Why it works: surprising to most learners, explains why long agent runs are slow and expensive, debunks a precise misconception, then delivers the real fix.
- Original source: OpenAI WebSocket Mode (Responses API) - https://developers.openai.com/api/docs/guides/websocket-mode
- Theo video: "I can't believe nobody's done this before..." - https://www.youtube.com/watch?v=sFEDAkJy9Dc
- Merge with: prompt cache invalidation in agent loops (https://www.anthropic.com/engineering/advanced-tool-use) and Dax's counter-intuitive tool-call pruning result (cleaning context breaks cache but is cheaper overall) from https://www.youtube.com/watch?v=131yAOjxHHQ.

**13. The Compounding Failure Tax: Why Tool-Call Reliability Beats Intelligence**
A model at 98% per-call tool accuracy drops to 90% end-to-end over 5 calls; a "smarter" 96% model drops to 80%, doubling the failure rate. Across a 200-call agentic run a 68% per-call provider is near-certain to fail. This makes benchmark intelligence nearly irrelevant for agentic model selection and surfaces a hidden axis: the inference provider's tool-call consistency (Moonshot's open K2-Vendor-Verifier shows respected providers at ~68%).
- Why it works: clean math hook, explains the Claude-for-agents default, introduces the under-discussed "provider is part of your reliability budget" idea.

**16. Why Senior Devs Accept MORE AI Code (Not Less)**

**19. The Hidden Bug in Every Retried AI Agent (It's new Date())**
When a durable workflow pauses and replays to resume, any non-deterministic call (new Date(), Math.random()) returns a different value on replay and silently corrupts state, so Vercel/Cloudflare/Convex all patch these globals. Pairs with Theo's combinatorial-failure math (0.5% + 1% + 1% step failures compound to 2 bad users per 100) and the durability-vs-longevity two-axis framework, for a complete "agentic reliability" episode that justifies durable-execution tools without distributed-systems prerequisites.
- Why it works: a "trap nobody warned you about" gotcha senior engineers also find valuable, highly shareable, with a clean 2x2 diagram.
- Original source: Tanner Lindsley "Directives and the Platform Boundary" - https://tanstack.com/blog/directives-and-the-platform-boundary

**20. The Auditor Pattern: Your Coding Agent Needs a Separate Review Agent**
Greptile's design philosophy (and Theo's personal workflow): the review agent must be architecturally separate from the coding agent, just as an auditor can't prepare the books they audit. One agent writes the PR, a separate agent reviews, findings loop back to the coder until clean, and humans enter only on ambiguity. This maps directly onto your existing reconciliation-loop curriculum and is buildable today with Claude Code subagents. Pairs with "you're reading the code too early" and the maker/checker split.
- Why it works: concrete multi-agent architecture students can wire up immediately, reframes when the human should enter the loop.
