Polling Is Dead

Hey friends,

Hope you're doing well.

Quick one this week about a new Claude Code tool that I think is going to quietly replace a lot of how I've been using agents lately.

It's called /monitor. And the easiest way to explain it is that it makes Claude Code event-driven instead of time-driven.

Here's what I mean. Before, if I wanted Claude to keep an eye on something like a dev server, a test run, or a deploy, I had two bad options. Option one: run the command in the foreground and get locked out of the terminal until it finished. Option two: run it in the background and only find out at the very end that 3 of my 47 tests failed, ten minutes after the fact.

Or I'd reach for /loop, which fires a prompt every N minutes and each iteration costs a full API call. Which works, but it's burning tokens the whole time just to check whether anything happened.

/monitor is different. You give it a description, a command, a timeout, and whether it should persist. Claude writes the filter for you. The filter only prints when something matches. And each print is one event that wakes the main session.

So if you're running a 10-minute test suite and ask Claude to "monitor only for failing tests," the moment a test fails, it gets pulled into the main session and Claude starts diagnosing it — before the other tests have even finished. Zero tokens spent waiting.

The video goes through the full mechanics, the four parameters under the hood, and the two shapes of monitors (stream filters vs poll-and-if filters). Plus a handful of use cases like file drop watchers, API price alerts, sales launches, and production deploys that I think a lot of you will get value from.

Agents Finally Sleep

Hey friends,

What I mean is — if I wanted Claude to keep watch over something (a dev server, a deploy, a long test run), it had to stay awake the entire time, checking in every 30 or 60 seconds. "Anything new yet? Anything new yet?" Each check burning tokens. Each iteration a full API call. And most of them returning nothing.

There's a new tool called /monitor that flips this. Instead of polling, Claude Code spins up a background process with a filter. That filter quietly runs for free. Zero tokens. And only when something you care about actually happens does it wake the main session up.

The mental shift that took me a minute to appreciate is that this isn't just "polling, but cheaper." It's a completely different shape. Your agent stops being a watchman pacing the corridor and becomes a motion sensor that only fires when something moves.

Wake On Event

The new feature is called /monitor. And it completely flips how background work gets handled.

Or background — which silently runs and only reports back once, right at the end, after everything has already happened. Which means you can start a 10-minute test suite, ask Claude to watch only for failures, and the moment something breaks, it's already diagnosing it. Not waiting until minute ten. Not polling every thirty seconds. Just… woken up, on demand, by the actual event.

The Primitive

Hey friends,

Hope you've had a good week.

Every so often, a new Claude Code feature ships that isn't really a feature — it's a primitive. A small, composable thing that changes what you can build with everything around it. This week's /monitor tool is one of those.

It takes four parameters. That's it.

A description of what to watch. A command to run. A timeout. And whether it should persist. Claude writes the filter for you, runs it in the background, and only wakes the main session when something matching fires.

The reason I keep calling it a primitive rather than a feature is that once you internalise what those four parameters give you, your whole mental model for long-running agent work shifts. It's event-driven, not time-driven. It's wake-on-signal, not poll-and-check. And because the filter runs silently in the background, there's basically no cost until something you actually care about happens.

Which is wildly different from /loop (time-driven, full API call every N minutes) and different from a plain backgrounded shell command (silent until it exits, then one big dump at the end).
