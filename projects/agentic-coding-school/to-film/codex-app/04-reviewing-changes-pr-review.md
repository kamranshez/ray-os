## Reviewing Changes & PR Review

This video is about review discipline.

Codex should not be treated as "prompt and accept." The production workflow is prompt, inspect, comment, revise, then accept.

## Big Picture

The diff is where trust is earned.

Students should learn to treat Codex changes like a junior developer's pull request: read the diff, question risky choices, leave feedback, and only then stage, commit, or ship.

## Teaching Line

> The workflow should not be prompt and accept. It should be prompt, inspect, comment, revise, then accept.

## Visual Variations

### Variation 1: Prompt To PR

Big idea: show a Codex change moving into a review lane before it reaches the final commit.

Core labels: prompt, change, diff, comment, revise, accept.

### Variation 2: Junior Developer Metaphor

Big idea: show Codex handing a pull request to the human reviewer.

Core labels: proposed change, risky part, inline comment, addressed.

### Variation 3: Diff As Safety Gate

Big idea: show the diff as a gate between generated code and the real project.

Core labels: generated change, review gate, revert, stage, commit.
