## Memory & Personalization

This video is about persistent preference and context.

Skills are explicit workflows you invoke. Memory is information Codex can carry forward into future work: preferences, corrections, project conventions, and hard-won context.

## Big Picture

Memory makes Codex less like a stateless assistant and more like a collaborator that learns your defaults.

This should be framed carefully because availability can depend on plan, region, and rollout.

## Teaching Line

> A skill is something you explicitly invoke. Memory is something Codex can carry with it into future work.

## Visual Variations

### Variation 1: Skill vs Memory

Big idea: compare an explicit reusable recipe with a persistent preference layer.

Core labels: invoke skill, remembers preference, future thread, same style.

### Variation 2: Preferences Travel Forward

Big idea: show a user correction becoming a memory card that follows Codex into the next thread.

Core labels: correction, saved preference, new thread, better default.

### Variation 3: Personal Context Layer

Big idea: show memory as a thin layer above projects, tools, and future conversations.

Core labels: tone, code style, commit style, project rules.
