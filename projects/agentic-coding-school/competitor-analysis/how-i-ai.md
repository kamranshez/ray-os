## Gaps Not Covered in Master Claude Code

- **[HIGH] Mermaid diagrams as context loading for Claude Code**: John Linquist demonstrates pre-loading mermaid diagram files (database schemas, auth flows, application architecture) into Claude Code's context at session start, so it doesn't need to explore the codebase. He generates these diagrams from code and stores them in a memory directory. Quote: "This is a way of visualizing database operations and it's a way of essentially compressing your application down into very small lines of text that show how your application works. Now for a human to read this, this is a big challenge. But an AI can consume this easily." Ray covers Git Diffs & Mermaid Diagrams but this is specifically about pre-generating and loading diagrams as reusable context.

- **[HIGH] Stop hook with TypeScript for automated type checking, error fixing, and auto-commit**: John shows a sophisticated stop hook written in TypeScript (using Anthropic's Claude Agent SDK) that: (1) checks if files changed, (2) runs `bun type check`, (3) if errors found, sends them back to Claude with instructions to fix, (4) if no errors, auto-commits with a meaningful message. The hook runs recursively until all errors are fixed. Quote: "We set up this workflow of once a conversation is finished, check to see if any files have changed. If they have, you check to see if there's any TypeScript errors... and if there are none, then go ahead and commit." Ray covers hooks and "Make Claude Speak to You" but not this specific auto-fix-and-commit stop hook pattern.

- **[HIGH] Using console.log as the communication channel from hooks back to Claude**: John explains a critical gotcha: hooks communicate back to Claude via the first console.log output (as a JSON object), and any other console.log from subprocess commands will interfere. He recommends using console.error for debugging and the `--quiet` flag for subprocesses. Quote: "It's going to find that first console log and whatever gets back, that's what it's going to see as its input. So you have to be careful... use console error or any other way of showing logs." Ray covers hooks but not this specific technical gotcha about stdout communication.

- **[HIGH] Shell aliases for different Claude configurations**: John demonstrates zsh aliases like `X` (bypass permissions), `H` (Haiku model), and `CDI` (load diagrams) to quickly launch Claude Code with different configurations from any terminal. Quote: "If you just type X now, anything I type has bypass permissions enabled. Or if I type H, this will be Haiku. It'll be much faster, but not quite as smart." Ray doesn't cover shell aliases for Claude Code launch modes.

- **[HIGH] GitHub Actions that auto-generate documentation and diagrams on PR merge**: The host (Claire Vio) describes running a GitHub Action that automatically generates documentation and mermaid diagrams when a pull request is closed. Quote: "I actually have a GitHub action that generates files almost exactly like you have with documentation and diagrams for new features of a specific scope. And so I do it when a pull request is closed and then I go back and update our diagrams." Ray doesn't cover this CI/CD integration for keeping context files up to date.

- **[MEDIUM] Building custom CLIs as personal tools using AI**: John shows "Sketch," a custom CLI he built that wraps Gemini to generate website design mockups based on guided prompts (niche, style, color theme, number of variations). He advocates building personal CLIs for recurring workflows. Quote: "Beyond the simple alias if you've never dived into creating what's called a CLI you can tell an AI... I want to use like this is a wrapper around Gemini where it will execute Gemini with specific prompts." Ray doesn't cover building custom CLI tools that wrap AI models.

- **[MEDIUM] Mermaid diagrams for compliance and customer-facing documentation**: Claire describes using mermaid diagrams generated from code to answer complex security questionnaires, SOC 2 compliance requirements, and create customer-specific data flow diagrams. Quote: "I use a lot of diagram generating out of our repo to answer very complex security and data flow requirements from our customers... if you're going through SOC 2 compliance or any compliance, these are assets that historically have just been so tedious to create." Ray doesn't cover this enterprise/compliance use case.

- **[MEDIUM] Dictation as primary prompt input method**: John uses dictation extensively for entering Claude Code prompts, noting the efficiency. The host calls it out: "Just how casually you use voice and transcription to enter in and out of these tools." Ray doesn't cover voice dictation workflows with Claude Code.

- **[MEDIUM] Hook types beyond basic logging -- linting, circular dependency checks, code complexity, duplicate code detection**: John lists numerous hook use cases: formatting, file length constraints, circular dependency checking, code complexity analysis, duplicate code detection across the codebase. Quote: "There's things like circular dependencies where I could check the imports to make sure that files don't reference each other. There's code complexity. There's tools that say does this code look like any other code in the codebase." Ray covers creating hooks but doesn't enumerate this breadth of use cases.

- **[MEDIUM] Using hooks for non-code workflows (document review, post-task completion checks)**: Claire suggests hooks can be used for non-coding tasks like post-document-completion quality checks. Quote: "Post-tool call hooks or post stop hooks in Claude can also be used when you're working on non-code... you could just think about what do I want automated after Claude finishes writing my document." Ray's hooks content focuses on code workflows.

- **[MEDIUM] Exporting conversation to another AI (ChatGPT/Gemini) for debugging when stuck**: John recommends exporting the conversation, dropping it into ChatGPT Pro or Gemini Deep Think for a "second set of eyes" critique, then starting over with a revised prompt. Quote: "Drop the conversation with some of the code files into ChatGPT Pro or Gemini Deep Think... have them do a second set of eyes on it and then kind of start over." Ray covers combining CLIs and models but not this specific "export and get a second opinion" debugging workflow.

- **[MEDIUM] IDE vs CLI debate and when each wins**: John gives a nuanced take on when terminal CLI (Claude Code) is better than IDE (Cursor) and vice versa. CLIs win for configuration, aliases, background execution; IDEs win for focused file editing, line selection, and extension ecosystems. Quote: "The CLIs have a lot of configuration and a lot of settings where I could launch a version of Claude that loaded up a specific set of MCPs or a specific set of prompts... currently inside of a cursor, there's usually a lot of okay open the UI, navigate to this." Ray doesn't directly address this CLI vs IDE comparison.

- **[LOW] "Easier to edit than author" philosophy for AI coding**: John articulates the principle that getting any output from AI, even if wrong, is better than starting from scratch because editing is easier than authoring. Quote: "It's easier to edit than author. So, let's get the authoring out of the way." This is a philosophy/mindset tip Ray could incorporate.

- **[LOW] Scaling hooks across engineering teams via settings.json (shared vs local)**: Claire emphasizes that hooks defined in settings.json (not settings.local.json) are shared across the team, and engineering leaders should designate someone to set up hooks for key repos. Quote: "If you haven't created these hooks for key repos... then you're missing out on some of the scaled leverage of these tools." Ray covers project vs user rules but not this specific team-scaling perspective for hooks.

- **[LOW] Exploring video as context format using Gemini**: John mentions using Gemini to process 6-hour workshop recordings, extracting notes, examples, and FAQs. Quote: "Recently built a tool that can take one of my six-hour workshops and process the entire thing and take out notes and examples." Not directly Claude Code related but interesting context about multi-modal workflows.
