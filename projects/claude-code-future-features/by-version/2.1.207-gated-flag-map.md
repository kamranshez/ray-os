### tengu_cobalt_harbor — Remote Control auto-enabled by default at session startup  
*rollout: gated · ungate: partial (server-gated) · video: 5/5*

Determines whether Remote Control (the bridge that lets the Claude mobile/desktop app monitor and drive a CLI session) turns ON automatically for every new session instead of requiring the user to run `/remote-control`. Code: `function Kan(){if(jN())return!1;if(xit())return!0;let e=jyi("remote_control_at_startup");if(e!==void 0)return e;return Qe("tengu_cobalt_harbor",!1)}`, consumed as `remote_control_auto_enable` in session-start telemetry: `p=!jN()&&(d??Kan())`. To keep a session in this terminal only, run /remote-control', shown when `e.replBridgeAutoOnByDefault` is true.

- **Gating:** No dedicated env var. `jyi("remote_control_at_startup")` first checks an org-managed policy default (from `policy-limits.json`, i.e. enterprise-controlled, not user-settable) and short-circuits the flag if set; otherwise falls through to `Qe("tengu_cobalt_harbor", false)` (server-flippable boolean).
- **Surface:** Session startup behavior - Remote Control (bridge to the Claude mobile app) becomes active without the user running any command; paired startup banner via tengu_cobalt_harbor_notice.

### tengu_copper_fox — Fork subagent (background subagent in an isolated git worktree)  
*rollout: gated · ungate: env+flag · video: 5/5*

A new built-in subagent type, `subagent_type: "fork"`, that inherits the FULL parent conversation context and runs in an isolated git worktree of the same repo. Its definition: `pY={agentType:'fork', whenToUse:'Fork — inherits full conversation context. ### tengu_doorbell_agave — Web-search / MCP-connector isolation latch (lethal-trifecta guardrail)  
*rollout: gated · ungate: partial (server-gated) · video: 5/5*

A prompt-injection/data-exfiltration mitigation: once a session touches EITHER (a) an external web tool (`web_fetch`/`web_search`, or a Chrome/browser MCP server matching `/^claude[-_](?:for|in)[-_]chrome$/i` or named 'Claude_Preview'/'Claude_Browser') OR (b) a non-exempt MCP 'connector' server, the session 'latches' onto that classification (`r.current=n`) via `DYr()`. Any subsequent tool call belonging to the OTHER classification is then denied with an explicit message: 'Connectors are unavailable in this session under your organization's web search / connector isolation policy. Start a new session to use connectors.' or 'Web search, web fetch, and browser tools are unavailable in this session under your organization's web search / connector isolation policy. Do not attempt to reach any external URL via another tool (curl, bash, the browser, or otherwise) — this policy blocks all outbound web access while connector data is in context. Start a new session to use web tools.' A fixed exempt-server allowlist (`uxs=['cowork','workspace','session-info','mcp-registry','plugins','scheduled-tasks','dispatch','ide']`) is excluded from the connectors classification. Denials are logged via `tengu_tool_use_isolation_latch_denied` telemetry and the latch state is persisted per-session ('isolation-latch' transcript entries, `isolationLatch` in session snapshots).

- **Gating:** `eky(){return Qe('tengu_doorbell_agave', false) && qyi('enforce_web_search_mcp_isolation')}` — requires BOTH the GrowthBook flag `tengu_doorbell_agave` true AND the named policy `enforce_web_search_mcp_isolation` to be `allowed===true` in the org's server-pushed `policy-limits.json` restrictions object (a separate enterprise policy system, fetched independently of GrowthBook via `pZ()`/`vIr()`). No CLAUDE_CODE_* env var found.
- **Surface:** No slash command; silently denies web_search/web_fetch/browser tool calls or MCP connector tool calls mid-session once the other category has been used, with the deny messages above surfaced as tool errors.

### tengu_cowork_chrome_automode_default — Auto-mode safety floor for 'Claude in Chrome' browser actions

### tengu_hazel_osprey — Server-side "context_hint" auto-pruning (Anthropic API beta context-hint-2026-04-09)  
*rollout: gated · ungate: flag · video: 4/5*

Opts the main interactive session into a new Anthropic API beta called `context_hint` (anthropic-beta header value literally `context-hint-2026-04-09`, from `Nmi=QA("context_hint","context-hint-2026-04-09")`). When active, every request from the main REPL thread (not subagents) sends `context_hint:{enabled:true, target_tokens_saved: <R1d()>}` in the body, asking the API to proactively trim/manage context server-side. The client also runs a matching local recovery path (`createContextHintController` / `cNy`): if the API rejects the request with 422/424 (`x1d`), the client strips the offending unprocessable content (oversized/corrupt images or documents — see `S1d`: "[Image/Document removed: the API could not process this ...]") from the message history and retries, logging telemetry event `tengu_context_hint_reject` with `preCompactTokenEstimate`/`postCompactTokenEstimate`/`tokensSaved`. Gated on `e.includeFirstPartyBetas` (first-party api.anthropic.com only) and `querySource.startsWith("repl_main_thread")`.

- **Gating:** No CLAUDE_CODE_* env var found. Two GrowthBook boolean/number flags, both server-flippable (not hardcoded): `A1d()=Qe("tengu_hazel_osprey",!1)` (master on/off, default false) and `R1d()=Qe("tengu_hazel_osprey_floor",aNy)` where `aNy=75000` (numeric target_tokens_saved sent to the API when >0).
- **Surface:** No direct slash command or visible UI — it's a background request-shaping/error-recovery layer around every API call in the main chat loop. User-visible effect (when triggered) is that a request that would otherwise hard-fail on an unprocessable image/PDF silently retries with that content stripped instead of showing an error.
