What changed in Claude Code **v2.1.209** vs the [[2.1.207-gated-flag-map|2.1.207]] baseline, extracted from the shipped binary on 2026-07-14. This is a **diff note**, not a full re-catalogue — it lists only what is new, shipped, or removed since 2.1.207. Method: string-dump both versions (`~/.claude/cache/binary-strings/2.1.20{7,9}.txt`), diff the `tengu_*` flag set and `CLAUDE_CODE_*` env set, then fan out subagents to trace each genuinely-new gate through the binary.

Installed version at time of scan: `2.1.209`. (2.1.208 was a same-day intermediate; the .209 dump supersedes it.)

## The raw diff

- **Flags:** 1611 → 1624 `tengu_*` names. **34 added, 21 removed.** Most additions are telemetry (`M(...)` event names), not gates.
- **Env vars:** 402 → 407 `CLAUDE_CODE_*`. **5 added, 0 removed:** `CLAUDE_CODE_ARTIFACT_MCP`, `CLAUDE_CODE_RC_PERMISSION_NUDGE`, `CLAUDE_CODE_FORCE_RC_LONG_TURN_NUDGE`, `CLAUDE_CODE_PROCESS_WRAPPER`, `CLAUDE_CODE_DISABLE_BEDROCK_CONTENT_TYPE_GUARD`.

Rollout-state legend as in [[2.1.207]]: 🟠 GATED (server-flippable, default off) · 🟡 ROLLING · 🟢 SHIPPED · ⚙️ INFRA/telemetry only.

## 1. Artifact MCP — published pages can call your connectors 🟠 (the headline)

The **Artifact tool** (internal codename **"Frame"**, `src/frame`) already shipped in 2.1.207: it renders an HTML/Markdown file to a default-private web page hosted on claude.ai (`POST /api/frame/deploy/*`), gated by `tengu_cobalt_plinth` + plan tier. **What's new in .209 is a capability layer on top of it.**

A published artifact can now declare **runtime capabilities** — specifically, the published claude.ai page's own JavaScript can call *the user's connected claude.ai MCP connectors* at runtime via a `window.claude.mcp.*` surface.

- **Gate:** `function c3y(){return sT.CLAUDE_CODE_ARTIFACT_MCP ?? Qe("tengu_cloth_snorkel",!1)}` (exported `isFrameMcpEnabled`). `sT` = `process.env`, so **`export CLAUDE_CODE_ARTIFACT_MCP=1` force-enables it directly** — nullish-coalesce env override, no Proxyman needed for *this* layer. Prerequisite: the base Artifact tool must already be on (`tengu_cobalt_plinth`, default false, + plan in team|enterprise|pro|max).
- **Proof it's new:** in 2.1.207 the module slot is dead (`var Dye=null`, so `Dye&&Dye.isFrameMcpEnabled()` was unconditionally false). In .209 it's wired: `__e=(eLs(),qn(y2d))`. All of `tengu_cloth_snorkel`, `CLAUDE_CODE_ARTIFACT_MCP`, `tengu_artifact_thumb_direct`, `tengu_artifact_disabled_session` = **0 hits in 2.1.207**.
- **How it works:** the tool schema grows `capabilities: {name: config}` and `contract: "latest"|"<semver>"` fields. Before writing any `window.claude.mcp` code, Claude Code must load a server-served skill `artifact-capabilities`, which fetches a **"roster"** + per-connector TypeScript `.d.ts` from claude.ai: `GET /api/frame/contract/latest` and `/api/frame/contract/{version}/prompt`. The **control plane (claude.ai), not the client, is authoritative** on valid capability names.
- **Safety guard (verbatim from prompt `Fuf`):** *"Never publish a page that calls a connector tool without having observed one real request/response pair for that tool in this session… Observed response payloads are the user's real data: learn the shape from them, but never embed the observed values in the published page as sample or placeholder data."* If a redeploy references never-observed connectors it fires `tengu_artifact_unobserved_connector_warning` (soft warning, not a block).
- **Base tool constants (unchanged):** 16 MB max file size (`a_e=16777216`); publish endpoints `/api/frame/deploy/{init,direct,complete}`; live-update `wss://…/edge-api/frame-live/{slug}/ws` (`frame-live.v1`). Base env gates: `CLAUDE_CODE_ARTIFACT`, `CLAUDE_CODE_DISABLE_ARTIFACT`, `CLAUDE_CODE_ARTIFACT_DIRECT_UPLOAD`, `CLAUDE_CODE_ARTIFACTS_API_BASE_URL`, `CLAUDE_CODE_ARTIFACT_AUTO_OPEN`.

**Verdict: video-worthy.** A claude.ai page you publish from the terminal can now call your own MCP connectors at runtime, governed by a versioned server-authoritative contract, with a real "don't publish calls you haven't observed" guard. Best new-feature story in this release.

**Sibling, not yet functional:** `tengu_artifact_thumb_direct` (client-side thumbnail capture via Chrome bridge on the direct-upload lane) is a **stub** — its getter `function iHs(){return null}` returns null unconditionally, so it's dead even with the flag on. `tengu_artifact_disabled_session` is pure telemetry (fires once/session when the tool is plan-eligible but env/settings-disabled).

## 2. Remote-Control nudges — "follow along on your phone" 🟠

"RC" = **Remote Control** (the existing feature that lets you approve tool calls / follow a session from your phone via a repl bridge; slash command `/remote-control`). Two new growth nudges upsell it. Both render as a persistent notification bar, priority "medium".

**`tengu_rc_long_turn_nudge`** — the live one. When a two-way Remote Control session is connected and a turn runs long, a bar appears: **`"Keep this running. Follow along on your phone · <session URL>"`**.
- Default config when flag is boolean-on: `{thresholdSec:90, probability:1, maxImpressions:3, dayStartHour:7, dayEndHour:21}` — fires after a 90-second turn, always shows, 3 lifetime max, **only 7am–9pm local time** (a genuine day-window growth mechanic). Clamps: `thresholdSec ∈ [5,3600]`, `probability ∈ [0,1]`.
- **Force locally:** `CLAUDE_CODE_FORCE_RC_LONG_TURN_NUDGE=1` (any truthy value) short-circuits to `{thresholdSec:5, probability:1, maxImpressions:-1, dayStartHour:0, dayEndHour:24}` — fires after 5s, unlimited, any time. Fastest demo: connect Remote Control, set the var, let a turn run 5s.
- Telemetry: `tengu_rc_long_turn_nudge_shown {auto_on, threshold_sec}`.

**`tengu_rc_permission_nudge`** — currently inert. Bar reads **`"Approve tool calls from your phone · <session URL>"`** after you hit N permission prompts in a Remote-Control session.
- Default config `b2o = {afterPromptCount:5, probability:0, maxImpressions:3}` — **probability 0**, so Anthropic hasn't turned it on. Shown only in `default|plan|acceptEdits` modes (never bypass).
- **Force locally:** `CLAUDE_CODE_RC_PERMISSION_NUDGE='{"afterPromptCount":1,"probability":1,"maxImpressions":99}'` (JSON override, not a boolean).
- Telemetry: `tengu_rc_permission_nudge_shown {permission_mode, prompt_count}`.

**Verdict:** the long-turn nudge is demo-worthy (visible, live-configured, day-windowed). The permission nudge is a good "hidden until forced" story but ships dead.

## 3. Memory rating write-back 🟠 (new)

Claude Code's file-based memory now **scores its own memories and writes the rating back into the memory file**. New in .209 (`tengu_memory_rating_writeback` = 0 hits in 2.1.207).

- A `memorySurveyRating` routine surveys which memory files were **cited** and **resolved** during a session, then appends a YAML block to the file:
  ```
  surveyRating:
    count: <n>
    mean: <x>
    total: <y>
  ```
  (field name `Jgf="surveyRating"`; constants `e1b=16`, buffer `o1b=262144`.)
- Telemetry: `tengu_memory_rating_writeback {cited_count, resolved_count, written_count}`.
- Note: the label `dream: "Background memory consolidation"` (a background task kind) already existed in 2.1.207 — only the *rating write-back* is new. This is the mechanism that lets memory quality self-tune over time.

**Verdict:** interesting for the auto-memory audience — memories that keep proving useful get a rising `surveyRating`. Worth a mention alongside the memory system.

## 4. Official-plugin prompt overrides 🟠 (new — trust story)

`tengu_official_plugin_prompt_overrides` lets **Anthropic remotely hot-patch the prompt text of first-party plugins/skills** without shipping a new CLI build. New in .209 (0 hits in 2.1.207).

- Gate: `let n=Qe("tengu_official_plugin_prompt_overrides",{}), o=X2g().safeParse(n)`. The GrowthBook payload is a `{pluginId: overrideEntry}` map; each entry is schema-validated (`J2g`); on failure it logs *"using baked-in text"* and falls back.
- Only applies to plugins whose source is in the **official allowlist** (`kw(r)` → set `T9t`): `claude-code-marketplace`, `claude-code-plugins`, `claude-plugins-official`, `anthropic-marketplace`, `anthropic-plugins`, `agent-skills`, `anthropic-agent-skills`, `life-sciences`, `knowledge-work-plugins`, … plus a second internal set `zWh`: `anthropic-skills`, `core`, `cowork-plugin-management`, `data`, `design`, `engineering`, `enterprise-search`, `figma`, `finance`, `human-resources`, `internal-apps`, `legal`, …

**Verdict:** notable trust/security angle — the prompts behind official plugins are server-mutable at runtime, gated to Anthropic's own marketplaces. Not a "feature" a user turns on, but a good explainer beat.

## 5. Background-agent daemon: launcher contract ⚙️ (infra)

A new indirection layer on the **existing** background-agent daemon (`claude daemon status/stop`, which supervises `claude respawn`-able worker sessions tied to a worktree). The daemon machinery itself is unchanged from .207; what's new is that it can now spawn workers **through a configurable wrapper** instead of exec'ing `claude` raw.

- New env var **`CLAUDE_CODE_PROCESS_WRAPPER`** (+ `jtt=12000` 12s timeout). The daemon enforces a formal **"launcher contract"** on the wrapper: contract #1 = must `exec`, not fork/daemonize; contract #3 = must pass `CLAUDE_CODE_PROCESS_WRAPPER` through to the child env.
- New telemetry (all 0 in .207): `tengu_bg_launcher_fork_and_exit`, `tengu_bg_daemon_spawn_launcher_fallback`, `tengu_bg_launcher_worker_refused`, `tengu_bg_respawn_downgrade_refused` (won't respawn to an older CLI version), `tengu_bg_launcher_replacement_raw`, `tengu_bg_reply_outcome`. `claude daemon status` gains a `launcher: <value>` line.

**Verdict: infra, not a headline.** Aimed at enterprise/managed fleets that need to wrap worker processes (sandbox/policy/observability shim). One line in a "what changed under the hood" segment.

## 6. Teleport branch guard ⚙️→user-visible (new failure mode)

`teleportToRemote` hands a session off to a cloud sandbox (`claude.ai/code`; the `CCR_*` "Claude Code Remote" / BYOC "Bring Your Own Compute" subsystem). In .207 the "reuse an existing branch as the outcome branch" path had **no collision check** — it just set `allow_unrestricted_git_push`. .209 inserts a guard.

- New: `tengu_teleport_on_branch_default_guard` (telemetry), `tengu_on_branch_default_guard_observe` (async gate), `tengu_bridge_outcome_branch_dropped`, `tengu_bridge_revision_guess_used` — all 0 in .207.
- Resolution: env `CCR_ON_BRANCH_DEFAULT_GUARD` > flag `tengu_on_branch_default_guard_observe` (observe vs enforce) > default **enforce**. Modes: **enforce** (reject reusing the repo's default branch — the runner's `git checkout -b` fails on a name the clone already has; suggests `--ref <branch>`), **observe** (warn but allow, for rollout telemetry), **pool** (self-hosted pools always allowed).
- `autofix_pr`-sourced sessions get a friendlier message pointing at a self-hosted BYOC env that tolerates it.

**Verdict:** a real user-visible behavior change (new denial when teleporting/Autofix-PR against your default branch) inside the larger cloud-handoff feature. Good anchor if Ray ever does a "teleport / cloud sessions" explainer — that subsystem isn't catalogued by name yet.

## How to reproduce this diff

```bash
cd ~/.claude/cache/binary-strings
for v in 2.1.207 2.1.209; do
  grep -oE '"?tengu_[a-z0-9_]+' $v.txt | tr -d '"' | sort -u > /tmp/flags-$v.txt
  grep -oE 'CLAUDE_CODE_[A-Z0-9_]+'  $v.txt | sort -u          > /tmp/env-$v.txt
done
comm -13 /tmp/flags-2.1.207.txt /tmp/flags-2.1.209.txt   # added flags
comm -23 /tmp/flags-2.1.207.txt /tmp/flags-2.1.209.txt   # removed flags
comm -13 /tmp/env-2.1.207.txt   /tmp/env-2.1.209.txt     # added env vars
```
Then classify each added name as gate (`Qe("...",…)`) vs telemetry (`M("...",{…})`) by grepping a char-window around it in the .209 dump.
