Every `CLAUDE_CODE_*` environment variable in the v2.1.207 binary, classified by **how big a behavioral change it makes**. Method + routine: [[README]]. Companion: [[2.1.207-gated-flag-map]] (GrowthBook flags).

Subagents grep-triaged all **402** env vars, then deep-explained the ones that actually change agent behavior (dropping pure infra-tuning, auth/transport, cosmetic-TUI, test, and dead vars). **163 behavior-changers** survived: **44 major, 60 moderate, 59 minor**.

`Ungate` legend: **env** = just export the var; **env+flag** = export it AND force the paired GrowthBook flag; **partial (server)** = the client honors it but a server/entitlement can still gate the real effect; **no (dead)** = named but no live read (setting it does nothing).

> Note on "DISABLE_" vars: many big-impact ones are **off-switches** for features that are ON by default. They're "major" because toggling them changes core behavior, but you'd use them to *turn things off*, not unlock hidden capability. Marked inline.

## Major — fundamentally change what Claude Code does

The vars that unlock a whole mode/tool/agent, change autonomy or safety, or gut a core subsystem.

### `CLAUDE_CODE_ARTIFACT` — Artifacts (Frame) master kill switch / entrypoint-restriction bypass
*partial (server)*

Master gate for an unreleased 'Artifacts'-style feature (internal codename cobalt_plinth / 'frame') that lets Claude Code deploy a hosted, shareable interactive web page from the session (POST /api/frame/deploy/init, auto-opened in the browser). String-typed env var (Fe.str()). In UXc(): `if(ou(be.CLAUDE_CODE_ARTIFACT))return!1` — any falsy string ('0','false','no','off') hard-disables Artifacts outright, overriding everything else. Conversely `if(!ct(be.CLAUDE_CODE_ARTIFACT)&&FXc())return!1` — a truthy value ('1','true','yes','on') bypasses FXc(), the check that normally blocks Artifacts for restricted entrypoints (claude-code-github-action, mcp, chat-relay backstop). - **Gating:** env AND flag tengu_cobalt_plinth AND server entitlement allow_cobalt_plinth (plan-gated, blocked for HIPAA/ZDR orgs); env alone can force-disable (kill-switch) but cannot force-enable without the flag+entitlement
- **Surface:** New capability: deploying/publishing an interactive hosted webpage ('frame') from a Claude Code session, auto-opened in the browser as a shareable link — analogous to claude.ai Artifacts but for Claude Code

### `CLAUDE_CODE_BUBBLEWRAP` — Bypass the root/sudo block on --dangerously-skip-permissions
*env*

`y5l(){return typeof process.getuid==="function" && process.getuid()===0 && process.env.IS_SANDBOX!=="1" && !be.CLAUDE_CODE_BUBBLEWRAP}` — Claude Code normally refuses to start with `--dangerously-skip-permissions` when running as root/uid 0 (`console.error("--dangerously-skip-permissions cannot be used with root/sudo privileges for security reasons"); process.exit(1)`), unless either `IS_SANDBOX==="1"` or `CLAUDE_CODE_BUBBLEWRAP` is set. - **Gating:** env-only truthy check (be.* proxy), functions purely as a safety-check bypass — inverted "kill switch" for a protective guard rather than a feature toggle
- **Surface:** CLI startup gate for `--dangerously-skip-permissions` (a.k.a. YOLO/bypass mode) when the process is running as root or via sudo

An explicit falsy value (0/false/no/off, checked via ou()) instead forces `{available:false, defaultOn:false}` — a secondary kill switch redundant with the dedicated CLAUDE_CODE_DISABLE_WORKFLOWS var.

- **Gating:** env OR flag tengu_workflows_enabled (default true) — the env var only overrides the *default-on* logic; it does not bypass higher-level gates evaluated in nE()/wIr(): org policy R1n()=Xi("allow_workflows"), managed-settings kill switch o5t() (disableWorkflows===true or CLAUDE_CODE_DISABLE_WORKFLOWS), and the user's own explicit settings.json `enableWorkflows` (peh(), which wins over defaultOn if set). So setting the var forces the feature on by default in the common case, but an org/managed lockout or an explicit user opt-out still wins.
- **Surface:** /effort ultracode; /config → Settings → "Dynamic workflows" toggle + "Ultracode keyword trigger"; the workflow() tool-call primitive Claude uses to run/nest named workflow scripts; 'Save as workflow' dialog offering Project (.claude/workflows/) or User (~/.claude/workflows/) scope; 'Dynamic workflows' onboarding/education dialog shown when first invoked.
