Imagine leaving Claude Code watching your production logs for 3 hours while you go to lunch.

Not polling them. Watching them. If error rates stay calm, you come back to a quiet terminal and a zero-token session. If they spike, Claude already has the stack trace, has started diagnosing, and has a message waiting for you.

That's what the new /monitor tool enables.

The primitive is simple → you give it a description of what to watch, a command, a timeout, and whether it should persist. Claude writes the filter. The filter only prints when things match. Each print wakes the main session.

It's like leaving a really attentive junior engineer in charge of the dashboards, except the junior only uses tokens when something actually happens.

This is the first Claude Code feature that changed what I feel comfortable walking away from.
