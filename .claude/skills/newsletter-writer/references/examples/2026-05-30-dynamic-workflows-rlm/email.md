Hey friends,

Hope you've had a great week.

About a year ago Claude Code shipped subagents, and I've been waiting for the next thing that felt like that big a jump ever since.

It just landed, and honestly it's now my favourite feature of Claude Code so far.

It's called dynamic workflows. I posted a quick video about it earlier today.

[VIDEO THUMBNAIL]

Up to now, if you used Claude as a subagent orchestrator, the model sat in the middle of every hand-off, passing most of the same context from one subagent to the next. The orchestrator's context window filled up, and it slowly got worse at the one job it had.

Workflows fix that. The orchestration lives in code now, not in the model's head. Subagents pass their results to each other directly through code, so the main model never fills up.

The feature is so powerful that the creator of Bun used it to rewrite a million lines into Rust in six days.

The more I use this, the more I think it's quietly turned Claude Code into something new: a recursive language model (RLM), a model that, when a job is too big for its own head, writes a program that runs more copies of itself. If Opus 4.8 has had special training to use dynamic workflows, it may be the first "RLM".

If you're interested in RLMs, the author of the paper has a great video about this and has been discussing the implications of "dynamic workflows" on X lately.

Have a great weekend :)

Ray
