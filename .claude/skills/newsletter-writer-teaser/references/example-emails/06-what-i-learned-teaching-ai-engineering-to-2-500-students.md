The next AI Coding for Real Engineers cohort opens soon. Class
begins June 1, save the date!

In April, I ran a brand new 2-week cohort class called Claude
Code for Real Engineers.

The idea was pretty simple: teach working engineers, like you,
how to use AI effectively on the kind of codebases you already
have: real, established, big, and sometimes messy. The method?
Real engineering practices, many of which go back decades before
coding agents became a thing.

I was expecting to sell ~800 to 1,000 seats.

We sold 2,500.

It blew me away.

In my heart, I knew just about every developer using LLMs could
get immense value out of this training.

But "real engineering" sounds a lot like "hard work" next to the
fantasy of letting an LLM do it all. And I wasn't sure how many
people would sign up for that.

And then 2,500 developers said, Yes! I want to learn to do things
the right way…

It made my year.

Because I believe that real engineering matters more than ever.
That LLMs don't get rid of engineering, they make it even more
urgent and important.

In a world of hype, it's so nice to know that so many people
care. Because, in a very real way, that's what engineering is:
caring. Caring about quality, safety and security, caring about
developer experience, caring about user experience, caring about
outcomes.

It was such a joy for me to share real engineering mindsets,
practices, processes and tools with 2,500 caring and committed
developers.

So is hearing things like this:

“During this course, I had ‘oh’ moments each time Matt described
these scenarios. My watch is now telling me how relaxed I am each
evening, whereas before it would tell me how stressed I was. And
I appear to have stopped swearing at my laptop. I have built my
own process from Matt's skills, I can see how it works, how it
will go about building my software, and I think I know how to
steer it.”

“I just got certified. And slightly humbled. Just finished
‘Claude Code for Real Engineers’ by Matt Pocock. 2 weeks. 6 days
of lessons. One uncomfortable realization: I was vibe coding with
a senior engineer's ego. The course reframed everything for me.
Claude Code isn't a better autocomplete. It's a junior engineer,
one that needs real engineering around it. PRDs. Feedback loops.
Context window discipline. The Ralph loop for autonomous, AFK
work. The scary part? The devs who skip this thinking are
shipping faster than ever. And drowning in debt they don't even
see yet. I'd be lying if I said the course didn't challenge some
habits I was proud of. But I left with a workflow I actually
trust.”

“8564 linting errors down to ZERO thanks to careful planning and
a Ralph loop. Huge shout out to @mattpocockuk and his Claude Code
for Real Engineers cohort. Wouldn't have been possible without
all the learnings from there.”

It's hard to capture how that feels.

I learned a lot too.

v1 was a great cohort. But it was still a v1. Together, my
students and I learned where the rough edges were, both in how I
was teaching, and in the tools we used.

v2 is launching soon(!), and I'm sanding off those rough edges.

The biggest one might surprise you: Docker Sandbox.

It's a great idea to have a sandbox to run your coding agents in
a safe way without also giving permissions 50 times an hour. But
Docker Sandbox specifically is tough to set up, tougher to
parallelize, and fundamentally not shaped like the thing active
developers actually need.

Docker Sandbox was annoying in class and it's more annoying in
everyday life.

So I'm fixing it, building a brand new sandbox tool, along with a
small handful of other things I'll talk about soon.

So…

If you want to learn to use AI like a real engineer, on a
real-life brownfield codebase, with the classical engineering
skills for heavy lifting…

The 2-week cohort starts June 1. Save the date!
